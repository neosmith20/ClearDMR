Test Checklist

1. Read from Radio, or load a .g77 file for read-only identity inspection.

2. Save Backup from that same fresh radio read before any hardware write.

3. Change either the boot text, the boot display mode, the callsign, or the DMR ID. DMR ID writes require an official current-ID confirmation match before the button enables.

4. Run exactly one isolated write button and wait for the immediate readback verify to pass.

5. Run Read Back & Verify after text changes, then save a fresh post-write backup if needed.

6. Power-cycle the radio and do another fresh read to confirm the setting persisted.

Callsign Notes

Callsign field: 0x00E0-0x00E7, 8 bytes, printable ASCII, padded with 0xFF.

Examples: W0PWR = 57 30 50 57 52 FF FF FF and TEST123 = 54 45 53 54 31 32 33 FF.

Guardrails: fresh Read from Radio required, Save Backup required, ASCII-only input, max 8 characters, pad unused bytes with 0xFF and never 0x00, write only 0x00E0-0x00E7.

Write flow: X 01 prepare 4 KB sector, X 02 overlay callsign bytes at 0x00E0, X 03 erase/program sector, then immediate readback verify of only the 8 callsign bytes.

After callsign write success, the session is marked stale and a fresh Read from Radio is required before any further write.

Edge Cases

1. Short callsign like A should encode as 41 FF FF FF FF FF FF FF.

2. Full 8-character callsign should use all 8 bytes with no padding.

3. DMR ID 3214246 should encode as 03 21 42 46.

4. DMR ID 3214288 should encode as 03 21 42 88.

5. Revert to the original callsign or DMR ID and verify again.

Protocol Notes

This page is the only place where the proven boot-text and boot-mode write paths are exposed for now. The main CPS page stays read-only until more write paths are hardware-proven.

Read path: open the port, clear only buffered accumulator state, then send direct R requests. No C 00 or C FE init commands are sent before reads.

Read responses: every response is treated as a strict R-framed packet. The reader sync-scans for 0x52, logs and discards any pre-sync bytes, then reads the big-endian payload length and exact payload.

Boot text write path on STM32: X 01 prepare the 4 KB sector containing 0x7540, X 02 overlay the 32 boot-text bytes, then X 03 erase/program the sector. X 04 must not be used on STM32 because it can ACK without modifying flash.

Boot display mode write path on STM32: X 01 prepare the 4 KB sector containing 0x7518, X 02 overlay exactly one byte at 0x7518, then X 03 erase/program the sector. Immediate readback must return 0x00 for Picture or 0x01 for Text.

Callsign write path on STM32: X 01 prepare the 4 KB sector containing 0x00E0, X 02 overlay exactly 8 bytes at 0x00E0-0x00E7, then X 03 erase/program the sector. Immediate readback must match the FF-padded ASCII callsign bytes exactly.

DMR ID write path on STM32: X 01 prepare the same 4 KB sector containing 0x00E8, X 02 overlay exactly 4 bytes at 0x00E8-0x00EB, then X 03 erase/program the sector. Immediate readback must match the packed-decimal bytes exactly.

Callsign guardrails: fresh Read from Radio required, Save Backup required, ASCII-only validation, max 8 characters, pad with 0xFF and never 0x00, write only 0x00E0-0x00E7, and mark the session stale after success.

DMR ID guardrails: known current ID confirmation from official CPS/radio required, input range 1-16776415, encode as 8 decimal digits left-padded with 0, store two digits per byte, write only 0x00E8-0x00EB, immediate readback verify, then mark the session stale.

Identity inspector: 0x00E0-0x00E7 is treated as callsign ASCII, FF-padded. 0x00E8-0x00EB is treated as packed decimal byte order: 03 21 42 46 -> 03214246 -> 3214246 and 03 21 42 88 -> 03214288 -> 3214288.

Codeplug file loads are inspection-only. Loading a .g77 file must not enable any write action until a fresh Read from Radio and Save Backup are completed.

Do not enable full-codeplug write here. This page remains an isolated hardware write lab.
